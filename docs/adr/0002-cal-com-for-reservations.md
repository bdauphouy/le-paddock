# Cal.com, embedded, for table reservations

Before this, booking a table meant calling the venue's phone number — there was no digital self-service option. A custom reservation engine (availability, party size, capacity, a staff-facing dashboard) was considered and rejected: the site has no backend beyond Sanity CMS, and building/maintaining one is disproportionate engineering effort for a single venue. Commercial restaurant platforms (TheFork, Zenchef, SevenRooms) were also rejected — all are paid or commission-based.

We integrated Cal.com's hosted free tier instead, embedded as an element-click popup. This is deliberately *not* modeled as a Sanity document — reservation/availability data lives in Cal.com, not in this codebase, an intentional exception to ADR-0001's pattern of "editable content lives in Sanity." The trade-off: Cal.com is a general-purpose scheduling tool, not restaurant-specific — no native table/capacity/party-size modeling, and reservation data isn't queryable from this codebase. In exchange, it's free at any realistic booking volume for a single-user setup, requires no backend of our own, and gives the venue owner a proven booking dashboard on Cal.com's side without us building one.
